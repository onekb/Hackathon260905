## 演示目标与开场

> InferPool 让买家带着单次预算选择独立推理卖家。卖家报价、预算锁定和按量结算在 Monad 测试网上执行；本次 AI 输出与 Token 计量是 Mock。我们演示的是一个资金规则真实可执行的推理市场原型。

先说明 **原生测试 MON 同时用于推理托管计费与链上 Gas；钱包须在存款之外预留 Gas**。正式产品没有旧 dUSD 操作入口。不把 AI 输出质量、真实模型验证或美元收入作为本次成果。

## 3 分钟压缩备用：一笔跨钱包交易讲清价值

以下时长是讲解安排，测试网与签名服务延迟不受此脚本保证。现场新单一旦不能及时确认，就展示原单状态并切到已确认的历史证据，不连续点击创建新单。

| 时间 | 操作 | 讲解要点 |
| --- | --- | --- |
| 0:00–0:25 | 显示市场当前在线卖家卡片 | “卖家通过独立进程接单并发布链上报价。买家可以自己指定；多个合格卖家在线时按预计总价匹配。” |
| 0:25–0:50 | 在现有 Para B 账户下，明确选择 A；预算 `0.001 MON`、最多输出 `512`，关闭模拟缓存；输入下方固定文本 | “输入便宜与输出便宜是不同卖点。这次我明确选 A，所以会发生 B 向 A 的跨钱包结算。” |
| 0:50–1:35 | 点击一次“运行请求”；指示锁款后才开始流式输出 | “先预留本次预算，再向节点派单；单次花费受预算约束。生成的内容和计量是 Mock。” |
| 1:35–2:15 | 等待账单“链上已确认”，显示用量、实际费用、已释放预算；打开结算交易 | “预留不是一次性扣完，按用量收取后，剩余预算回到可用托管余额。文字输出结束不代表结算已经确认。” |
| 2:15–2:45 | 打开新 MON 卖家失败 smoke 的公开回执 | “卖家中途失败，包含已经输出的部分在内，整单推理费为零；已发生的链上 Gas 不退。” |
| 2:45–3:00 | 回到市场或 API 接入示例 | “网页与程序使用同一个市场。链上约束资金，Router 负责链外计量和判责；真实模型接入是后续工作。” |

固定输入：

```text
用三个要点解释：链上托管如何保护买家的推理预算？
```

旧 dUSD 配置的历史跨钱包单为 `69a28714-618a-4d8b-99c5-620cba33e728`：输入 `54`、输出 `187`，费用 `0.016580`、释放 `0.083420 dUSD`。它仅存档，不在 MON 产品内展示或重标；新 MON 单以自己的账单为准。该单 [结算交易](https://testnet.monadscan.com/tx/0x2bdb839417b6ac90d78d42d910d3e8bbaad915c41e480dffbb7a3cc721fb3754) 与 [独立对账记录](../contracts/deployments/inferpool-smoke-market-monad.json) 已保存。

## 5 分钟正式版：真实交易、责任规则与技术挑战

正式版按下表执行，固定输入与正常单配置见上面的压缩版。主线包含一笔正常跨钱包请求和一笔故障订单；其他能力用已确认账单或只读结果说明。计时前准备好钱包、资金和授权，给链上确认留出时间；若切换历史证据，明确告知观众。

| 时间 | 操作 | 讲解要点 |
| --- | --- | --- |
| 0:00–0:25 | 显示市场当前在线卖家与开场一句话 | “我们构建可设预算、可选卖家的推理市场；AI 是 Mock，资金交易是真实 Monad 测试网操作。” |
| 0:25–1:30 | Para B 指定 A，预算 `0.001 MON`、最多输出 `512`、缓存关闭，使用固定输入，只点一次运行；展示锁款后开始流式响应 | “卖家各自报价；这笔请求会从 B 钱包向 A 结算。预算先锁定，实际费用不会超过预算。” |
| 1:30–2:00 | 显示链上已确认账单与结算交易 | “实际用量决定费用，余款释放。报价版本、用量、费用和交易可以对账；未确认的单据要明确标记待确认。” |
| 2:00–2:55 | 确认 A 没有活动订单；在 A 控制台把“新订单运行模式”改为“输出中途失败”；买家仍指定 A，发送一笔新的 `0.001 MON` 预算请求 | “这是主动注入的 Mock 故障。看见部分内容后卖家失败，最终整单推理费应为零。”必须等链上已确认再宣称本单免单 |
| 2:55–3:25 | 对比正常单与故障单的费用和释放；确认故障结束后把 A 恢复“正常完成” | “预算是上限，最低预留是接单条件；卖家失败不是只免除没生成的部分。” |
| 3:25–4:10 | 显示当前报价与旧双卖家市场存档，明确旧证据资产 | “短输入、较大输出上限会选输出便宜的 B；长输入、小输出上限会选输入便宜的 A。匹配依据是估价，最后仍按实际用量收费。” |
| 4:10–4:40 | 显示 API 接入示例，指向单次预算、幂等 Key 与查询订单方式；再用归档记录解释缓存/取消规则 | “开发者通过统一 Router 调用，不需要卖家的公网地址；断开流连接不等于取消。缓存读写分价，买家主动取消按已使用量收费。” |
| 4:40–5:00 | 指向节点认证及原锁款失败证据，简述挑战与创新 | “关键挑战是让网页钱包认证独立节点而不导出私钥，以及锁款不明时不重复派单。我们把分项报价、预算、故障责任与链上账单连成一条流程；计量和判责仍信任 Router，真实模型尚未接入。” |

旧 dUSD 市场脚本已从当前产品删除，不再运行旧 `test:market:monad`。直接阅读公开 JSON 和区块浏览器即可讲解历史；三笔 API 汇总含 A 买 A 的角色重合，另一浏览器手动单是 B 买 A。新 MON 的同钱包八笔 [合约 smoke](../contracts/deployments/inferpool-native-monad-smoke.json) 与旧跨钱包结果分开，不能合称新 MON 多钱包或公网 SSE 已通过。

## 故障备用演示

| 现场情况 | 处理与可展示材料 |
| --- | --- |
| 新单锁款迟迟不明或结算未确认 | 保留请求 ID，显示实际状态，查询同一订单；不要换幂等 Key 盲发推理，也不要口头确认成功。切换到下方已有交易。原锁款失败只有在到期和链上/Router 共同确认后才执行过一次受限恢复，这不是通用自动重试 |

## 已知限制与演示结束

输出、Token、缓存都是 Mock；Router 受信计量和判责，平台与接单卖家可见请求内容。合约不验证模型身份、质量或链外用量。没有 TEE、质押罚没或无需信任推理证明，也没有真实收入或性能基准承诺。

MON 版配置/模型、API 34 批 SSE，以及 B 的网页存款/授权和正常/故障两单已通过。尚未验证当前 MON 版浏览器取消、提款、撤销授权、离线回收、断连/幂等、钱包切换及逐帧 SSE；这些不因正常/故障付款通过而扩大。对应实现或底层测试存在，不替代实际浏览器验证；最新范围以进度页为准。Alchemy 无交易引用异常根因尚未明确，演示前需继续关注提交稳定性。

结束时把故障模式恢复 normal，确认没有遗留待处理订单，保存本次新请求 ID 与最终回执；若创建了临时 API Key，结束后撤销。录屏或截图仅在实际生成并检查过后再登记链接，当前没有交付视频。
